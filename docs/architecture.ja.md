# アーキテクチャ

[English](architecture.md)

`jellycli`では、ターミナル表示、Jellyfinとの通信、プレイヤー制御を分離し、それぞれを独立してテスト・変更できるようにしています。

```text
cmd/jellycli
    |
    +-- コマンド・設定層
    |       |
    |       +-- Jellyfin HTTPクライアント
    |       +-- 再生オーケストレーション
    |
    +-- Bubble Tea TUI
            |
            +-- ナビゲーションと画面状態
            +-- 共通のクライアント・再生サービスを呼び出すコマンド

再生オーケストレーション
    |
    +-- ソース選択（Direct Play / Direct Stream / Transcode）
    +-- mpvプロセスとJSON IPC
    +-- Jellyfin再生セッション通知
```

## 各領域の役割

| 領域 | 役割 |
| --- | --- |
| CLIエントリーポイント | コマンド解析、設定読み込み、CLIまたはTUIの選択 |
| TUI | 画面遷移、検索入力、読み込み・エラー状態、ユーザー操作の管理 |
| Jellyfinクライアント | 認証とJellyfin HTTP APIからGo型への変換 |
| 再生 | メディアソース選択、`mpv`の起動・監視、セッション状態の通知 |
| 設定 | サーバー情報と認証情報を非公開権限で保存 |

## 再生の流れ

1. 選択したJellyfinアイテムを解決し、再生情報を取得する。
2. 利用可能なDirect Play、Direct Stream、Transcode URLを選択する。
3. ローカルIPCエンドポイントを指定して`mpv`を起動する。
4. Jellyfinへ再生開始を通知する。
5. IPCを通じて再生位置、一時停止、シーク、終了を監視する。
6. 定期的に進捗を送信し、最後に停止または完了状態を通知する。

OS固有のプロセス処理とIPC処理は再生層の内側に閉じ込めます。特にWindowsの名前付きパイプ対応をTUIやJellyfinクライアントへ漏らさない設計とします。

詳細な設計判断と実装フェーズは[design.md](design.md)を参照してください。
